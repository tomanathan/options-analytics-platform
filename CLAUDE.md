# options-analytics-platform

Option chains and daily prices land in Iceberg (bronze), dbt builds silver, gold and the analytics on DuckDB (Snowflake is the unprovisioned prod target), Airflow orchestrates, Great Expectations gates bronze, and a calibration backtest plus put credit spread engine scores spreads. See README.md and docs/architecture.md.
Status: Phases 0-3 built and verified locally (two bronze tables, eight DAGs, dbt silver/gold, seven analytics models, report). Cloud targets (Snowflake, S3/Glue, Alpaca) are configured, not provisioned; never claim a run on them. Phase 4 (FRED rate, Snowpark) is not started.

## Layout
- `src/oap/{ingest,engine,analytics,quality}/`, `src/oap/calendar.py` (NYSE calendar). `tests/` mirrors the code.
- `oap.ingest.tables`: one `TableSpec` per bronze table (`OPTION_CHAIN`, `UNDERLYING_PRICE`); writer, reader, merge and maintenance are generic over it.
- `src/oap/engine/`: pure numpy functions (conventions, black_scholes, implied_distribution, calibration, spread_scoring).
- `src/oap/analytics/`: calibration backtest and spread scoring over frames (`config`, `sample`, `backtest`, `scoring`; only `io` touches a relation).
- `src/oap/api/` (FastAPI explorer API: only `db` and `store` touch the DuckDB file, read-only) and `apps/web/` (React explorer; `openapi.json` is generated by `make api-schema`, never hand-edited).
- `dags/`: DAGs plus `common.py` (defaults, pool, `fail_fast`), `datasets.py`, `dbt_runner.py` (dbt and report commands, `duckdb_writer`), `timetables.py`. `plugins/oap_timetables.py` registers `NYSECloseTimetable`.
- `dbt/`: project `oap`. `models/{staging,intermediate}` silver, `models/marts` gold, `models/analytics` Python models (tag `analytics`), `macros/register_bronze.sql` pins the snapshot, `tests/` singular tests.
- `scripts/`: `iceberg_count.py`, `make_synthetic_bronze.py`, `make_report.py`, `image_requirements.py`, `refresh_bronze.py` (DoltHub to bronze without Airflow; the nightly job). `.github/workflows/{ci,nightly}.yml`. `docker/`, `infra/` (Terraform).
- `docs/`: architecture, runbook, ADRs 0001-0012, and `results.md` with `img/` (generated by `make report`; do not hand-edit; `img/explorer.png` is the one hand-captured image). `design/explorer-v1.md` is the explorer spec. The README block between the `results` markers is generated too.

## Conventions
- Python 3.12, `uv`, `ruff` (Google docstrings), `mypy --strict`, `pytest` + `hypothesis`.
- Engine code is pure, no I/O. Every docstring states units: dollars per share, vol as decimal, time in years (ACT/365), rates as decimal APY (ADR 0009).
- Analytics models are thin wrappers over tested pure functions in `oap.analytics` (ADR 0010). Calibration is walk-forward: the map for year Y trains only on expirations before 1 January of Y.
- A new bronze table is a new `TableSpec`; write only through `write_partition` or `merge_into_slices` (ADR 0003). The quality gate runs before the write.
- Any task that commits to bronze runs in `pool=BRONZE_WRITERS_POOL`; any task that opens `oap.duckdb` runs in `DUCKDB_POOL`. Put `@fail_fast` under `@task`. A DAG that produces data lists the Dataset in `outlets`.
- DAGs on the market calendar use `NYSECloseTimetable`, not cron. Do not import one DAG module from another.
- dbt resolves bronze through the `register_bronze` hook and `OAP_DBT_SOURCE` (ADR 0008). Underlying prices are as traded, not split-adjusted (ADR 0007).
- dbt: every model has `schema.yml` descriptions on every column and at least two tests. Portable SQL for DuckDB and Snowflake (ADR 0002); Python models are DuckDB-only.
- Dependency changes: edit `pyproject.toml`, `uv lock`, `make lock-export`, `make airflow-build`. The image installs from the lock (ADR 0006).
- Conventional commits: `feat(ingest): ...`, `chore(infra): ...`, `docs(decisions): ...`. Non-obvious design choices get a Nygard-format ADR.

## Checks
- `make check` (lock-check, lint, typecheck, test, dbt-compile, dbt-build on synthetic bronze) must be green before every commit.
- `make web-check` (explorer lint, format, typecheck, tests, schema drift, build) runs separately and in the CI `web` job. Also `make tf-validate`, `make compose-config`. pre-commit runs `detect-secrets`, ruff and hygiene hooks.
- Hooks: ruff formats every Python file you edit; `uv run pytest -q` runs when you stop and blocks on failures.
- Only one process may write `.dbt-local/oap.duckdb`; do not run `make dbt-build-local` or `make report` while `dbt_build` or `score_spreads` runs.
- The `nightly` workflow (ADR 0012) refreshes bronze in the cloud and commits only `docs/results.md`, two figures and `README.md`; `make pull-gold` replaces `.dbt-local/oap.duckdb` with its artifact (stop `make serve` and the stack first), `make nightly-run` and `make nightly-status` drive it.

## Adding things
- Python: `python` agent; test at the mirrored path. dbt model: `/model <layer> <name>`. DAG: `/dag`. Docs and ADRs: `docs` agent. Review: `/review`.

## Never
- Never commit data, `.env`, credentials, keys, state files or `*.duckdb`. `data/`, `.dbt-local/` and `.iceberg-local/` are gitignored.
- Never put real secrets in `.env.example`; use obvious placeholders.
- Never leave placeholder text or unfinished-work markers in code or docs; write "Phase N will ..." instead.
- Never describe unbuilt behaviour as existing. Never skip hooks (`--no-verify`).
